# Operations

## Install (local)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,reporting]"      # extras: ai, freqtrade
```

Settings are read from the environment or `.env` (prefix `QTS_`):

| Variable | Default | Meaning |
|---|---|---|
| `QTS_CONFIG_FILE` | `configs/default.yaml` | YAML config used when `-c` is not given |
| `QTS_DATABASE_URL` | `sqlite:///state/qts.sqlite` | operational database |
| `QTS_STATE_DIR` | `state` | kill-switch state |
| `QTS_LOG_LEVEL`, `QTS_LOG_JSON` | `INFO`, `true` | logging |

## Commands

```text
qts config                         validate and print the configuration
qts data download | check          refresh / verify history
qts data export-freqtrade          write candles in Freqtrade's format
qts backtest [--start --end]       backtest vs Buy & Hold (saved to the DB)
qts validate                       full validation report
qts paper start [--from DATE]      open a paper session (--from replays history: demo only)
qts paper step                     process candles closed since the last step (idempotent)
qts paper run                      service loop: step every --interval-minutes
qts paper status | stop
qts risk status | kill | reset
qts health                         DB, data freshness, kill switch, heartbeats (exit 1 on failure)
qts db init
```

Expected failures print one `ERROR:` line and exit with code 1; they are also
written to the structured log.

## Docker stack

```bash
cp .env.example .env    # replace every change-me
docker compose up -d --build
```

| Service | Purpose | Port (localhost only) |
|---|---|---|
| `postgres` | operational database (+ `freqtrade` DB, read-only `grafana_ro` role) | 5432 |
| `paper-trader` | `qts paper run` with `configs/paper.yaml` | — |
| `grafana` | dashboard *QTS — Trading overview* | 3000 |
| `freqtrade` (profile) | Freqtrade dry-run + API/UI | 8080 |
| `backup` (profile) | one-shot `pg_dumpall` into `./backups` | — |

## Paper trading

The paper trader downloads newly closed daily candles, runs the strategy,
passes every order through the risk engine and books simulated fills. A decision
taken at the close of day *D* is filled at the open of *D+1* and appears once the
*D+1* candle is complete. Changing the configuration requires a new session
(`qts paper stop` then `start`) so results stay attributable to one config.

## Dashboard

Select a run (paper session or any saved backtest) at the top. Panels: initial
capital, equity, P&L, return, drawdown, equity vs Buy & Hold, Sharpe/Sortino/CAGR/
win rate/profit factor, cash and exposure, open positions, trades, risk decisions
and events, service heartbeats, active sessions, errors and system log. The
dashboard is generated by `scripts/build_dashboard.py`.

## Monitoring errors

- `docker compose logs -f paper-trader` — JSON logs, secrets redacted;
- Grafana → *System* row — heartbeats and the `system_events` table;
- `qts health` — suitable for cron or an external monitor.

## Backups

```bash
scripts/backup.sh     # pg_dumpall -> backups/qts-<stamp>.sql.gz (keeps the last 14) + state archive
```

`backups/` is git-ignored and created with restrictive permissions: copy the
files off the machine. Restore instructions are in the script header. Price
history does not need backups: it is re-downloadable and checksum-verified.
